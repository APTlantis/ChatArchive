# ChatArchive withdrawn release policy

If a published package is found unsafe, materially defective, or incorrectly documented, stop describing it as current, preserve the release evidence, record the reason and affected package identity, and use the Store/Partner Center withdrawal or update path appropriate to the incident. Do not rewrite historical evidence. Notify affected operators through the release notes and provide recovery guidance for local libraries. A replacement package receives a new monotonic Store package version and full release-gate evidence.
